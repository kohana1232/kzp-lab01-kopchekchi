## 1. Мета роботи

Ознайомитися з основами створення консольних програм мовою Java, навчитися працювати з текстовими файлами, перевіряти коректність вхідних даних, обчислювати числові показники та формувати звіт.

## 2. Постановка завдання

Відповідно до варіанта 11 необхідно розробити консольну програму для обробки даних аптеки.

Кожен запис містить п'ять полів:

- `name` — назва препарату (String);
- `form` — форма препарату (String);
- `price` — ціна (double);
- `daysToExpire` — кількість днів до завершення терміну придатності (int);
- `prescription` — ознака рецептурності (boolean).

Програма повинна обчислювати чотири показники:

1. Кількість коректних записів.
2. Середню ціну препаратів.
3. Мінімальну кількість днів до завершення терміну придатності.
4. Кількість рецептурних препаратів.

Некоректні записи необхідно пропускати з повідомленням про номер рядка та причину помилки.

## 4. Хід виконання роботи

### 4.1. Підготовка середовища

Встановлено JDK 21 та налаштовано середовище Visual Studio Code для роботи з Java.

Під час першого запуску виявлено конфлікт версій: компілятор `javac` використовував Java 21, а команда `java` — Java 8.

Після зміни порядку шляхів у змінній середовища `Path` для поточного термінала програму вдалося запустити.

Також налаштовано кодування UTF-8 для правильного виведення українських символів.

### 4.2. Створення проєкту

Створено проєкт `Lab1_Apteka` з основними каталогами:

- `src/` — вихідний код програми;
- `data/` — вхідні CSV-файли;
- `out/` — результати компіляції та звіти;
- `ai/` — опис ролей ШІ.

Передбачено файли `README.md`, `REPORT.md`, `.gitignore`, `.gitattributes` та `.editorconfig`.

### 4.3. Реалізація програми

У файлі `src/Main.java` реалізовано:

- читання текстового файлу в кодуванні UTF-8;
- розділення записів на поля за символом `;`;
- перевірку кількості полів;
- перевірку текстових і числових значень;
- перевірку невід'ємності ціни та кількості днів;
- перевірку значень `true` і `false`;
- обробку некоректних записів без аварійного завершення;
- обчислення чотирьох показників;
- виведення результатів у консоль;
- збереження звіту в текстовий файл.

Програма підтримує параметри `--help`, `--input` та `--output`.
Після початкової реалізації було проведено рефакторинг програмного коду. Логіку розділено на окремі методи: `readData()` для читання файлу, `processLine()` для перевірки записів, `updateStatistics()` для обчислення показників, `createReport()` для формування звіту та `saveReport()` для збереження результатів. Після рефакторингу повторно перевірено звичайний запуск, обробку некоректних записів і параметр `--help`. Усі перевірки пройшли успішно.
### 4.4. Компіляція та запуск

Команда компіляції:

```powershell
javac -encoding UTF-8 -d out src/Main.java
```

Команда запуску:

```powershell
java -cp out src.Main
```

Запуск із власними шляхами:

```powershell
java -cp out src.Main --input data/input.csv --output out/test.txt
```

# Лабораторна робота №2

**Тема:** Класи, record і інкапсуляція в Java-проєкті  
**Варіант:** 11 — «Аптека»  
**Рівень виконання:** 1  
**Мова програмування:** Java 21  
**Середовище:** Windows, Visual Studio Code

## 1. Мета роботи

Навчитися створювати власні класи Java, використовувати інкапсуляцію, конструктори з перевіркою інваріантів, статичні фабричні методи та незмінні типи `record`.

Виконати рефакторинг програми лабораторної роботи №1, зберігши її функціональність і результати обчислень.

## 2. Опис предметної області

Програма «Аптека» обробляє CSV-файл із відомостями про лікарські препарати.

Для кожного препарату зберігаються:

- Назва.
- Форма випуску.
- Ціна.
- Кількість днів до завершення терміну придатності.
- Ознака рецептурності.

Програма визначає кількість коректних записів, середню ціну, мінімальну кількість днів до завершення терміну придатності та кількість рецептурних препаратів.

## 3. Зміни порівняно з лабораторною №1

У першій лабораторній CSV-дані оброблялися безпосередньо в `Main.java`.

У другій лабораторній створено окремий клас `Medicine`, який представляє один препарат.

Основні зміни:

- Дані препарату об'єднано в об'єкт.
- Поля зроблено `private final`.
- Перевірку правильності значень перенесено до конструктора.
- Реалізовано метод `Medicine.fromCsv()`.
- Додано геттери та метод `toString()`.
- Створено допоміжний `record ExpiryPrescription`.
- Обчислення статистики виконуються на основі списку об'єктів `Medicine`.

## 4. Клас Medicine

Клас `Medicine` містить п'ять приватних незмінних полів: `name`, `form`, `price`, `daysToExpire`, `prescription`.

Конструктор перевіряє такі інваріанти:

- Назва та форма не можуть дорівнювати `null` або бути порожніми.
- Ціна повинна бути невід'ємним скінченним числом.
- Кількість днів не може бути від'ємною.

Для читання полів реалізовано геттери.

Метод `toString()` формує текстове представлення препарату із форматуванням ціни до двох знаків після коми та використанням `Locale.ROOT`.

## 5. Метод fromCsv()

Статичний фабричний метод `Medicine.fromCsv()` перетворює CSV-рядок на об'єкт `Medicine`.

Метод перевіряє кількість полів, перетворює числові значення та перевіряє, чи дорівнює значення рецептурності `true` або `false`.

За некоректних даних генерується виняток. Під час читання файлу програма повідомляє номер помилкового рядка та продовжує обробку інших записів.

## 6. Record ExpiryPrescription

Створено `record ExpiryPrescription`, який містить:

- `daysToExpire` — кількість днів до завершення терміну придатності.
- `prescription` — ознаку рецептурності.

Record використовується під час обчислення статистики.

Його значення незмінні після створення. Додатково реалізовано перевірку невід'ємності кількості днів.
